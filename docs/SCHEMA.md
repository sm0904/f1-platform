# Database schema

This document describes the database in plain language. The SQL is the source of truth:
`persistence/src/main/resources/db/migration/`. Each section names the migration that created the table.

Version: V1 (historical results). Prediction tables are added in V2.

---

## How the tables fit together

Everything hangs off the season and the race. A **season** holds many **races**. Each race takes place at one
**circuit** and holds one **session** per competitive type (qualifying, sprint qualifying, sprint, and race).
Each session holds many **session results**, one per driver entry. A result links to the **driver** who drove
and the **constructor** (team) that entered the car.

```
season ─┬─< race >── circuit
        │     │
        │     └─< session >─< session_result >── driver
        │                             │
        │                             └── constructor
```

The `<` means "one to many". A race has one session of each type, so the session table has at most one row
per race and type.

---

## Identifiers and provenance

Every table except `season` has an internal `id` generated by the database. Each row also has a `source_key`,
which records the identifier the data provider gave it (for example, the Jolpica driver ID `hamilton`). The
loader matches rows by `source_key`, so re-running a load updates existing rows and never duplicates them.
Internal IDs are never taken from the provider. This keeps the provider's naming out of our keys.

Two identifiers are deliberately **not** unique, because they were reused over the decades:

- A driver's three-letter code (`HAM`) and permanent car number.
- A car number within a season.

Uniqueness for results is therefore defined on the entry, not on these reused values (see `session_result`).

---

## season

Migration: V1. One row per Formula 1 championship year.

- **year**: the calendar year, primary key.
- **Rule:** the year must be 1950 or later. The championship began in 1950, and the data starts there.

## circuit

Migration: V1. One row per track, whether or not it has hosted a race in the database.

- **id**: internal identifier.
- **source_key**: the provider's circuit identifier, unique.
- **name**: the circuit's display name. Must not be blank.
- **locality** and **country**: where the circuit is. Optional, because the provider doesn't always give them.

## race

Migration: V1. One row per Grand Prix weekend in a season.

- **season_year**: the season the race belongs to. Must match a row in `season`.
- **round**: the race's position in the season, starting at 1.
- **name**: the Grand Prix name, for example "British Grand Prix". Must not be blank.
- **circuit_id**: the circuit where it was held.
- **race_date**: the date of the race itself.
- **Rules:**
  - The round must be at least 1.
  - Within a season, each round number appears only once.

A race is identified by its season and round, not by its name, because some names repeat across years.

## session

Migration: V1. One row per competitive session in a race weekend.

- **race_id**: the race the session belongs to.
- **type**: one of `QUALIFYING`, `SPRINT_QUALIFYING`, `SPRINT`, or `RACE`.
- **source_key**: the provider's session identifier. Optional in the schema, but the loader always sets it.
- **Rules:**
  - Only the four competitive types are allowed. Practice sessions are out of scope.
  - A race can have at most one session of each type.

## driver

Migration: V1. One row per driver.

- **source_key**: the provider's driver identifier, unique. This is the only uniqueness rule for drivers.
- **code**: the three-letter code, if the driver has one. Must be three uppercase letters when present.
- **permanent_number**: the driver's permanent car number, when one exists. Must be positive when present.
- **given_name** and **family_name**: the driver's names. Both are required.
- **nationality**: optional.

Codes and permanent numbers are not unique. They were reused across eras, so the table does not constrain them.

## constructor

Migration: V1. One row per team. Teams often change names, so a constructor's identity is its provider key,
not its name.

- **source_key**: the provider's constructor identifier, unique.
- **name**: the team's name at the time it was loaded. Must not be blank.
- **nationality**: optional.

## session_result

Migration: V1. One row per driver entry in a session. This is the largest table.

**Identity.** A result is identified by its session, driver, and car number together. This is the rule that
matters for the historical data. From 1950 to 1964, some drivers drove two cars in one race, for example when
a team changed cars after a crash. Those are two valid entries with two car numbers. A rule forbidding one
driver twice in a race would reject real history. The rule is therefore: one entry per session, driver,
and car number.

**Fields.**
- **car_number**: the number on the car for this entry. Positive when present. It is empty when the provider reports no number: withdrawals in 1961 to 1963 have none, and 1973, 1993, and 1994 use a placeholder 0, which the loader stores as empty. Because SQL treats empty values as distinct, the database does not enforce the uniqueness rule for these rows. The loader enforces it instead: the same driver cannot appear twice in one session with no number.
- **position**: the official classified position. Empty when the driver is not classified.
- **position_text**: the provider's raw position text, kept as received. For example, `1`, `R` for retired, or `D` for disqualified.
- **status**: our classification, derived from the position text and the status text (see below).
- **status_detail**: the provider's raw status text, such as "Engine" or "+2 Laps". Kept for audit and never used to decide the status.
- **grid**: the starting position. Zero means the pit lane. Empty where the provider has none, for example in qualifying.
- **laps**: the number of laps completed.
- **time_text**: the race time or gap, as given by the provider.
- **points**: the points scored, with one decimal place. Half points were awarded in some early seasons.
- **q1**, **q2**, **q3**: qualifying times, kept as text. Three formats occur: `m:ss.mmm`, `mm:ss.mmm`, and `ss.mmm`. Parsing them is the loader's job.

**Status values.** `CLASSIFIED`, `RETIRED`, `DISQUALIFIED`, `EXCLUDED`, `WITHDRAWN`, `NOT_CLASSIFIED`.

**Rules.**
- A `CLASSIFIED` result must have a position. Classified means the official classification ranked the car.
- Position, grid, and laps must be positive or zero where they are present. Car number must be positive where present.
- Points cannot be negative.

**Indexes.** Lookups by driver and by constructor are indexed, because the insight and standings queries
group by them.

The full mapping from provider text to status is in `docs/STATUS_MAPPING.md`.

## Relationships and deletes

Foreign keys have no cascading deletes. Removing a season, race, session, driver, or constructor that other
rows still refer to is rejected by the database. Loads only ever insert or update, so this protects the data.

## prediction_run (V2)

Migration: V2. One row per frozen prediction for one target race.

- **model_name** and **model_version**: which model produced it, and its parameters (for example `elo-pl`, `k32-lambda0.5`).
- **target_season**, **target_round**, **target_name**, **target_date**: the race being predicted. The race is not
  in the `race` table, because it has not happened yet.
- **data_cutoff_date**: the date of the last race whose results the model could see. Must be before the target date.
- **input_races**: how many completed races fed the model.
- **grid_known**: false for a pre-qualifying prediction, true once the starting grid is known.
- **simulations** and **random_seed**: the Monte Carlo settings, so a run can be reproduced exactly.
- **parameters**: the full set of model settings, as JSON.

A run is unique per target race, model version, and grid status. Once stored, it is not overwritten.

## prediction (V2)

Migration: V2. One row per driver in a run.

- **rating_strength**: the driver's combined driver and constructor strength on the Elo scale.
- **win_prob** and **podium_prob**: probability of finishing first or in the top three. Each is between 0 and 1,
  and the podium probability is never less than the win probability.
- **expected_position**: the average finishing position across the simulations. At least 1.

The probabilities assume the whole field takes the start. The model does not yet estimate retirements, so each driver's chance of finishing is treated as certain.
